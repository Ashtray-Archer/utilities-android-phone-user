# Green Grocer

An offline, session-only sample catalog and cart, intended as a small native
application whose semantic state can be inspected independently of Android.
The selected interaction and architecture are in [star-review.md](star-review.md).

The one-screen NativeActivity builds for A1 and C67. Browse eight products,
adjust amounts, remove products, switch to selected products, scroll, and read
the exact total. The cart lasts for the process session. [execution.md](execution.md)
separates host tests, Android builds, candidate packaging, producer approval,
and the still-unrun physical acceptance.

## Independent cart core

[model/cart.h](model/cart.h) exposes catalog validation, add, set amount,
remove, amount lookup, total and derived browse/selected rows.
[model/cart.c](model/cart.c) has no Android or renderer dependency.
[fixtures/catalog.c](fixtures/catalog.c) supplies eight sample package products;
its NULL image keys deliberately request local placeholders in a later renderer.

The catalog must be immutable, contain unique nonzero identity tokens and have
at most 64 products. A zero-initialized cart is empty. Only its populated prefix
is state: unique catalog identities with positive 32-bit amounts. This fixed
storage bound keeps allocation outside the specimen; it is not a proposed
limit for real stores. Names and units may repeat. Catalog ordering can change
without changing cart identities.

Money is unsigned 64-bit sample USD cents. Both multiplication and accumulated
sum are checked. Each transition validates the incoming state, changes a local
candidate, checks the candidate total, then commits it. Unknown products,
invalid state, out-of-range amounts and monetary overflow leave state unchanged.
Zero set amounts remove entries; removing an absent known product is a no-op.
Errors do not repair corrupt state by silently omitting products.

Browse and selected rows follow catalog order. Row amounts, subtotals and the
grand total are projections, never cached cart state. The selected-product
count is `cart.count`; it differs from the sum of unit amounts. Filtering belongs
to presentation. The renderer must consume these outputs rather than maintain
a parallel quantity or money model.

[model/cart_test.c](model/cart_test.c) contains independent expected totals,
boundary transitions and deliberately invalid states. The source files for
the bounded semantic executable are exactly `model/cart.c`,
`fixtures/catalog.c` and `model/cart_test.c`. They require C17 and the target's
standard C library. The selected build path is **ICK + NDK**: ICK compiles
`model/cart.c` and `fixtures/catalog.c`; NDK compiles the target verification
runner and later Android adapter, and links the ICK-produced objects. Each
compile/link stage is recorded separately. The host lane executes the tests
and passes. Both Android lanes compile/link the same tests; their target
execution remains **NOT_RUN**.
An ICK failure or missing required capability must be reported to the user with
the exact pin and reproducer. Do not silently recompile the core with NDK.

The separate [Idriç attempt](../examples/autogenerated/green-grocer-cart/attempt.md)
typechecks and emits its actual one-step handoff. The DEX backend rejects the
cart function ABI. It does not participate in the application build.

## Build boundaries

Run the maintained Grease helpers on a verified build host, using absolute paths.
Each prints its full argument interface when invoked without arguments.

- [_/check-core.grease](_/check-core.grease): pinned ICK objects, NDK runner/linker,
  required canonical ai-ci preflight, and source/tool/output digest receipts.
  Targets: `host`, `a1`, `c67`.
- [_/build-native.grease](_/build-native.grease): validates the matching core
  receipt, compiles the Android adapter with NDK, then links the ICK objects.
- [_/package-native.grease](_/package-native.grease): validates the native receipt
  and invokes the maintained `android-NDK` NativeActivity packager. Package,
  version, ABI, alignment, signer and absence of DEX are checked.

`8bf8be153f792c4def251287ed85543d1fe24f07`, NDK to r29 `29.0.14206865`,
